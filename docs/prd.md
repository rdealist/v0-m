## 1. 背景与目标

### 1.1 问题陈述

中国现有超 3285 项医学影像检测项目，但 AI 辅助诊断渗透率不足 1%。核心障碍在于：高质量、有标注的医学影像训练数据严重匮乏。医院拥有数据但无力组织标注；专业医生有标注能力但缺乏平台和激励。

### 1.2 产品定位

一个连接**数据持有机构**与**专业标注医生**的众包协作平台。机构发布数据与任务，医生完成标注并获得积分激励，Lv5+ 专家负责质量审核，形成可闭环的数据标注生态。

### 1.3 预览版目标

| 目标 | 度量指标 |
|------|---------|
| 验证核心业务闭环可用性 | 完整跑通"上传→发布→领取→标注→审核→结算"全流程 |
| 邀请种子用户内测 | 支持 50 名内测医生 + 10 家机构同时使用 |
| 验证标注工作台体验 | 标注者平均每例完成时间 < 5 分钟 |
| 技术稳定性基线 | 100 并发下 P95 响应时间 < 500ms |

## 2. 用户角色

### 2.1 角色总览

| 角色 | 入口条件 | 核心诉求 |
|------|---------|---------|
| **游客（L0）** | 未注册或未登录 | 了解平台，浏览公开数据集和任务 |
| **标注者（Lv1-Lv4）** | 注册并通过基础认证 | 领取任务、完成标注、赚取积分 |
| **专家（Lv5-Lv9）** | 标注者通过资质晋升 | 标注 + 审核他人成果、收取审核费 |
| **机构** | 注册并通过机构资质认证 | 上传数据集、发布标注任务、管理质量 |
| **管理员** | 内部账号 | 平台治理、资质审核、争议处理 |

### 2.2 等级体系

| 等级 | 名称 | 核心能力 | 晋升条件（预览版简化） |
|------|------|---------|------------------|
| L0 | 游客 | 浏览公开内容 | — |
| Lv1 | 新手 | 接受 Lv1 任务 | 完成注册 + 邮箱验证 |
| Lv2 | 初级 | 接受 Lv1-2 任务 | 累计完成 50 例标注 |
| Lv3 | 中级 | 接受 Lv1-3 任务 | 累计完成 200 例，通过率 ≥ 80% |
| Lv4 | 高级 | 接受全部标注任务 | 累计完成 500 例，通过率 ≥ 85% |
| Lv5 | 专家 | 标注 + **审核权限** | 提交资质申请，管理员人工审核 |
| Lv6-9 | 资深/权威/首席/顶级专家 | 审核权限（扩展） | 预览版暂不开放，后续迭代 |

## 3. 功能模块

### 3.1 注册与认证

#### 用户故事
- 作为访客，我希望用邮箱注册账号，以便进入平台
- 作为新注册用户，我希望收到验证邮件确认身份
- 作为用户，我希望用邮箱+密码登录，并保持登录状态 7 天
- 作为机构代表，我希望提交机构资质材料，等待管理员审核通过后获得机构权限

#### 功能点
- 邮箱注册（含邮件验证码确认）
- 邮箱 + 密码登录
- 忘记密码（发送重置链接）
- 会话持久化（7 天自动续签）
- 机构资质认证申请（提交营业执照图片，状态：待审核 / 已认证 / 已拒绝）
- 管理员后台：查看并审批机构认证申请

#### 验收标准
- [ ] 注册后邮箱收到验证邮件，点击链接后账号激活
- [ ] 未验证邮箱的用户无法领取任务
- [ ] 登录后刷新页面保持登录状态
- [ ] 机构用户未认证时，发布任务按钮显示"认证后可用"
- [ ] 管理员审批后，机构用户立即获得发布权限

### 3.2 数据广场

#### 用户故事
- 作为浏览者，我希望看到平台上所有公开数据集，以便评估数据质量
- 作为浏览者，我希望按影像模态（CT/MRI/X-Ray等）和科室筛选数据集
- 作为机构用户，我希望上传 DICOM 数据集并填写元数据，发布到数据广场
- 作为机构用户，我希望在发布前预览我的数据集信息

#### 功能点
- 数据集列表（分页，默认按创建时间倒序）
- 多维筛选：影像模态、科室、状态、样本数范围
- 关键词搜索（数据集名称、机构名）
- 数据集卡片：名称、机构、模态、科室、样本数、价格、状态徽章
- **数据集上传流程**（分步表单）：
  - Step 1：填写基本信息（名称、模态、科室、描述）
  - Step 2：上传 DICOM 文件（前端直传 COS，最大单文件 2GB，支持批量）
  - Step 3：填写定价和访问权限，提交
- 上传后状态为 `draft`，管理员审核通过后变为 `public`（预览版简化：机构提交后直接变 `public`）

#### 验收标准
- [ ] 筛选条件组合使用时结果正确
- [ ] 上传进度条实时更新
- [ ] 上传完成后数据集出现在"我的数据集"
- [ ] 非机构用户看不到"上传数据集"按钮

### 3.3 任务广场

#### 用户故事
- 作为标注者，我希望浏览所有开放任务，了解奖励和等级要求
- 作为标注者，我希望一键领取适合我等级的任务
- 作为机构用户，我希望基于已上传的数据集创建标注任务，并设定奖励和审核要求
- 作为专家（Lv5+），我希望看到待审核任务队列

#### 功能点
**所有用户可见：**
- 任务列表（全部任务 Tab）：任务名、发布机构、奖励积分、最低等级、截止日期、领取进度条
- 筛选：影像模态、最低等级要求、排序（最新/截止最近/奖励最高）
- 任务详情展开：描述、每例单价、总例数、已领取/最大名额

**标注者（Lv1+）：**
- 领取任务（等级不足时按钮置灰，显示所需等级）
- "我的接单" Tab：进行中的任务、标注进度、截止日期
- 点击"去标注"进入标注工作台

**专家（Lv5+）：**
- "审核任务" Tab：待审核的标注提交列表（提交人、提交时间、例数）
- 点击"开始审核"进入审核工作台

**机构用户：**
- "我发布的" Tab：已发布任务、锁仓积分、领取进度
- 发布任务入口（需机构认证）

**发布任务表单：**
- 关联数据集（从我的数据集中选）
- 填写任务名称、描述
- 设定：每例奖励积分、最大领取人数、最低等级要求、截止日期
- 预算预览：总锁仓 = 每例积分 × 总例数 × 最大人数 × 1.05（5% 平台手续费）
- 提交时从钱包扣除锁仓积分（余额不足时阻止提交）

#### 验收标准
- [ ] 等级不足的任务对该用户显示为不可领取，按钮提示所需等级
- [ ] 并发领取时同一任务名额不超额（测试：同时提交 30 个领取请求，最大名额 20，结果只有 20 人成功）
- [ ] 发布任务后钱包余额减少，锁仓金额增加
- [ ] 余额不足时无法提交任务（前端实时计算 + 后端校验双重保障）

### 3.4 标注工作台

#### 用户故事
- 作为标注者，我希望在工作台看到 DICOM 影像，并对病灶进行标注
- 作为标注者，我希望标注结果自动保存，防止意外丢失
- 作为标注者，我希望完成全部例数后一键提交，等待专家审核
- 作为标注者，我希望看到当前任务的进度和预计收益

#### 功能点
**布局**：三栏（左：例数缩略图列表，中：DICOM 影像查看区，右：标注表单/备注）

**影像查看：**
- 支持影像模态：CT、MRI、X-Ray、OCT（预览版）
- 窗宽/窗位调节（W/L）
- 放大/缩小（滚轮）
- 图像平移（按住拖拽）
- 序列翻页（CT 多层）

**标注工具（预览版）：**
- 矩形框选（ROI）
- 标注分类标签（从任务定义的类别中选择）
- 自由文字备注（每例一个文本框）
- 清除当前例的标注

**进度管理：**
- 左侧缩略图显示已完成/进行中/待完成状态
- 顶部进度条：已完成 X / 共 Y 例
- 自动保存：每 30 秒 + 切换例时 + 离开页面时
- 手动保存按钮

**提交：**
- 全部例完成后"提交审核"按钮激活
- 提交后任务状态变为"待审核"，不可再编辑

  "annotatorId": "user-uuid",

      "label": "malignant",
      "handles": {
        "start": { "x": 120, "y": 85 },
        "end": { "x": 210, "y": 160 }
      }

  "note": "边界清晰，考虑恶性",

#### 验收标准
- [ ] 打开工作台 3 秒内影像加载完成（本地测试，COS 同区域）
- [ ] 切换例时自动保存上一例的标注
- [ ] 刷新页面后标注数据不丢失
- [ ] 提交后无法再进入标注，显示"待审核"状态

### 3.5 审核工作台

#### 用户故事
- 作为 Lv5+ 专家，我希望看到标注者提交的标注结果叠加在原始影像上，评估质量
- 作为专家，我希望逐例审核，可以通过或拒绝每一例的标注
- 作为专家，我希望审核通过后积分自动结算给标注者和我自己

#### 功能点
**布局**：与标注工作台相似，但右侧显示标注者的标注结果（只读叠加显示）

**审核操作（每例）：**
- 通过（Pass）
- 拒绝（Reject）+ 必填拒绝原因
- 部分修改（预览版不含，后续迭代）

**批量操作：**
- 全部通过

**审核完成：**
- 所有例审核完成后，触发积分结算
- 审核结果通知标注者

**积分分配规则：**
```
标注者获得 = 每例奖励 × 通过例数
专家获得   = 每例奖励 × 通过例数 × 5%（审核费）
平台手续费 = 已在发布时锁仓的 5%，不再额外扣除
拒绝例对应积分退还机构（从锁仓释放）
```

#### 验收标准
- [ ] 专家只能看到自己等级 ≤ 当前等级的标注者提交的任务（Lv5 专家可审核 Lv1-Lv4 标注者）
- [ ] 审核完成后标注者和专家的钱包余额立即更新
- [ ] 拒绝例的积分正确退还给机构
- [ ] 机构可以在任务详情中查看审核结果明细

## 4. 业务流程

### 4.1 核心标注闭环

```
机构注册并通过认证
    │
    ▼
上传 DICOM 数据集 → 填写元数据 → 数据广场展示
    │
    ▼
创建标注任务 → 设定奖励/等级要求 → 积分锁仓 → 任务广场展示
    │
    ▼
标注者浏览任务广场 → 领取任务（扣减名额）
    │
    ▼
进入标注工作台 → 逐例完成标注 → 自动保存
    │
    ▼
全部完成 → 提交审核 → 任务状态变为"待审核"
    │
    ▼
Lv5+ 专家收到通知 → 进入审核工作台 → 逐例审核
    │
    ├── 通过 → 对应积分从锁仓划转给标注者
    │          5% 审核费划转给专家
    │
    └── 拒绝 → 对应积分从锁仓退还给机构
    │
    ▼
结算完成 → 双方收到积分变动通知
```

### 4.2 机构资质认证流程（预览版简化）

```
机构用户提交认证申请（营业执照图片 + 机构名称）
    │
    ▼
申请状态：待审核
    │
    ▼
管理员在后台查看申请 → 通过/拒绝
    │
    ├── 通过 → 用户角色更新为 institution → 收到通知
    └── 拒绝 → 显示拒绝原因 → 用户可重新提交
```

## 5. 非功能需求

### 5.1 性能

| 指标 | 目标值 |
|------|--------|
| 页面首次加载（LCP） | ≤ 2.5 秒 |
| API 响应时间（P95） | ≤ 500ms（标注保存除外）|
| 标注自动保存响应 | ≤ 1 秒 |
| DICOM 影像首帧加载 | ≤ 3 秒（同区域 COS）|
| 并发承载 | 100 并发用户 |

### 5.2 安全

- 所有 API 需携带有效 Session Token，否则返回 401
- DICOM 文件通过预签名 URL 访问，有效期 1 小时，不可猜测
- 密码使用 bcrypt（cost factor 12）加密存储
- 管理员操作接口单独鉴权（admin role）
- 上传文件类型校验（白名单：.dcm、.zip、.jpg、.png）
- API 限流：注册/登录接口 10 次/分钟/IP

### 5.3 数据

- 标注数据不可删除（软删除）
- 积分流水不可删除、不可修改（只增加记录）
- 用户数据满足《个人信息保护法》要求（最小必要原则）
- DICOM 文件需去标识化（预览版提示用户自行处理，平台不自动执行）

### 5.4 可用性

- 服务可用率目标：99.5%（允许每月约 3.6 小时停机）
- 数据库每日自动备份，保留 7 天
- 标注数据每 30 秒自动保存，防止丢失

## 6. 预览版发布标准

所有以下条件满足，方可对外开放内测：

**功能完整性（P0，必须全部通过）**
- [ ] 注册/登录/退出流程无报错
- [ ] 完整跑通一次端到端业务闭环（上传→发布→领取→标注→审核→结算）
- [ ] 积分结算金额计算正确（验证 3 个以上用例）
- [ ] 标注工作台在 Chrome/Safari/Edge 最新版均可正常使用

### 8.3 访问策略闭环

为消除“游客可浏览”与“所有 API 需要登录”的矛盾，预览版采用以下策略：

| 资源/动作 | 游客 | 已登录用户 | 机构 | 专家 | 管理员 |
|-----------|------|------------|------|------|--------|
| 浏览公开数据集/任务列表与详情 | 允许，只返回公开元数据 | 允许 | 允许 | 允许 | 允许 |
| 获取 DICOM 临时 URL | 禁止 | 仅 claim owner 或授权审核专家 | 仅 owner 或授权流程 | 仅授权审核任务 | 允许 |
| 领取任务 | 禁止 | 按等级允许 | 不作为标注者时禁止 | 按等级允许 | 禁止或仅测试环境 |
| 发布数据集/任务 | 禁止 | 禁止 | 认证通过后允许 | 禁止 | 允许治理操作 |
| 钱包、我的任务、通知、认证材料 | 禁止 | 仅本人 | 仅本人/本机构 | 仅本人 | 管理员按后台权限 |

技术规格必须据此拆分公开只读 API 与登录后动作 API。

### 8.4 去标识化与合规边界

预览版不实现自动 DICOM Worker 去标识化；但为了满足医学数据安全边界：

- 上传入口必须提示并要求机构确认：上传数据已完成去标识化或为合成/样例数据。
- 后端必须记录确认声明、提交人、时间和数据集 ID。
- 未确认时不得发布数据集，也不得创建标注任务。
- 日志、通知、错误信息不得包含患者姓名、身份证号、住院号、出生日期等 PHI。
- 自动去标识化、DICOM Worker 预处理仍属于后续版本非目标。

### 8.5 状态机与账本不变量

技术实现必须至少满足以下状态与不变量：

1. 数据集：`draft/uploading → ready → public → archived`。
2. 任务：`open → closed → completed/cancelled`。
3. 领取：`in_progress → submitted → settled`，允许审核结果按 case 混合通过/拒绝。
4. 审核：`assigned → in_review → completed`，完成动作必须幂等。
5. 钱包：只增流水；余额、锁仓、待结算由流水或视图派生，不维护可被并发覆盖的余额字段。
6. 结算：同一 claim/audit 的结算必须有幂等键，重复请求不得重复发放奖励、审核费或退款。
7. 公开浏览：匿名接口只能返回公开元数据，不得返回私有对象存储 key 或临时下载 URL。
